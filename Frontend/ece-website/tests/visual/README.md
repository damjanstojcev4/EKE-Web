# Privacy Policy visual baseline

Shared UI's opt-in real-API capture and actual-component gallery suites are documented in `docs/SHARED_UI_TAILWIND_PHASE3.md` at repository root. Run browser suites serially. Their separate software-rendered whole-page reference does not replace these approved Privacy Policy images.

Run from the frontend directory after `npm run build`:

```powershell
npx playwright test --config playwright.visual.config.ts
```

This is opt-in; `.visual.ts` files are intentionally excluded from the existing default `.spec.ts` integration suite. Snapshot files are copied byte-for-byte from the audit's actual staging Privacy Policy captures, not generated by accepting local output.

- Capture: 24 November 2026 Europe/Skopje, UTC timestamp in audit manifest
- Windows Edge: `158.0.4370.33`, DPR 1, reduced motion
- Desktop 1440×1000, tablet 820×1180, mobile 390×844
- Local suite uses en-GB, Europe/Skopje and light color scheme; privacy content is static and makes no API requests
- Strict comparison: zero changed pixels, threshold zero

The initial local comparison passed all three staging images without updating them. The existing integration suite separately uses controlled API fixtures; this page's visual test aborts any unexpected API request. No CMS record is created or changed. The snapshots establish privacy-page parity, not all-site integration parity.

Keep Edge at the recorded revision for repeatability. Browser upgrades or Linux Chromium need separately reviewed baselines. Never update all snapshots merely to resolve a failure. Keep all current breakpoints, SVG clipping and variable-font behavior unchanged in the pilot. Add 700/701 and 1100/1101 boundary comparisons before removing replaced CSS.
