## API contracts

All paths below are relative to `/api`. Browser requests use the shared typed API
layer and same-origin credentials, with `cache: no-store`. Server API/media responses
also use no-store. Errors use HTTP 400 for validation, 401 anonymous management,
403 role/CSRF, 404 missing/hidden details and 409 duplicate slugs/references.
No token is stored in browser storage. Login/session/CSRF retain Phase 1 contracts.
For a cookie-authenticated mutation, GET `/auth/csrf`, send the returned token in
`X-XSRF-TOKEN`, and retain the CSRF/auth cookies. Existing bearer clients remain supported.

### News

| Method/path | Request | Response |
| --- | --- | --- |
| GET `/news/homepage` | None | Array, latest 3 eligible published News, timestamp then ID descending |
| GET `/news/public` | `page=0`, `size=12` (1–100), optional `category=LATEST_NEWS` or `OPEN_CALL` | Spring Page: `content`, `number`, `size`, `totalElements`, `totalPages`, `first`, `last` and standard paging metadata |
| GET `/news/slug/{slug}` | Public slug | Full eligible News or 404, even for authenticated admins |
| GET `/news/public/{id}` | ID | Public-only related article lookup |
| GET `/news`, `/news/{id}` | Existing contract | Admin sees managed records; anonymous sees only eligible records |
| POST `/news`, PUT `/news/{id}` | Multipart fields below; ADMIN | Saved full News |
| DELETE `/news/{id}` | ADMIN | 204 |

News response fields: `id:number`, `shortDescription:string`, `instagramUrl:string`,
`imageUrl:string|null`, `createdAt:local-date-time`, `title:string|null`,
`category:LATEST_NEWS|OPEN_CALL|null`, `imageAlt:string|null`, `publishedAt:instant|null`,
`published:boolean|null`, `slug:string`, `emphasis:string|null`, `introduction:string|null`,
`contentJson:string|null`, `heroUrl:string|null`, `heroAlt:string|null`,
`relatedIds:string|null`, `updatedAt:instant|null`, `placement:string|null`,
`mediaKind:string|null`, `mediaUrl:string|null`.

Multipart write fields are the same editable names except IDs/timestamps/media URLs
generated by storage: `image` and `hero` are optional image files; `mediaUrl` is an
optional external HTTP(S) audio/video source. Omitted fields/files retain values.
`placement`: LATEST, FEATURED, BIG_STORY, COMMUNITY, MEDIA. `mediaKind`: empty, AUDIO,
VIDEO. `relatedIds`: comma-separated numeric IDs. Links resolve through public-only
reads and only generated target routes become clickable.

Slugs: lowercase letters/digits separated by hyphens, maximum 160, database unique.
New News without a supplied slug gets `news-<random UUID>`; legacy migration uses
`news-<id>`. Publishing requires the Phase 1 title/summary/category/time and image-alt
rules, plus hero alt when a hero exists. Future publication instants stay hidden.

`contentJson` is a JSON-encoded array (max 100 blocks / 100,000 characters):

```json
[
  {"type":"heading","text":"Heading"},
  {"type":"paragraph","text":[{"text":"Text","strong":true},{"text":" Link","href":"https://example.org"}]},
  {"type":"list","items":[{"title":"Item","text":"Explanation"}]}
]
```

These are schema examples, not seeded editorial content. No raw HTML rendering.
The server validates block shape/size and HTTP(S) links; React escapes text, and
the frontend separately checks rendered URLs.

### Projects

GET `/projects/`, `/projects/recent`, `/projects/get/{uuid}` and legacy title reads
remain. GET `/projects/public?status=ON_GOING|PAST` returns a deterministic ID-descending
array; GET `/projects/slug/{slug}` returns the selected project or 404.

POST `/projects`, PUT `/projects/{uuid}` remain multipart; DELETE remains UUID-based.
All writes require ADMIN and cookie CSRF. Existing required fields are title, budget,
description and quickSummary; update requires status. Optional start/end dates,
repeated partners fields, image and PDF retain their established contract. Cover
image is now optional for new records; no placeholder content is invented.

New editable fields: slug, programme, grantValue (decimal, nonnegative), currency
(three uppercase letters), countries (editorial text), keyAction, actionType,
website (HTTP(S)), topics (comma-separated), contentJson (News block schema), imageAlt,
downloadDescription, resourcesJson, partnerMediaJson. `logo` is an optional image file.
Response retains `uuid`, title, budget, description, `image` (URL), `pdfUrl`,
quickSummary, startDate, endDate, partners array, status, date, and adds all metadata
above plus `logoFilePath`. Existing UUIDs, files and associations are preserved.

POST `/projects/media` accepts one multipart `file`, returns `{"url":"/api/uploads/..."}`.
Use its managed URL in JSON fields:

```json
{"resourcesJson":"[{\"title\":\"Resource title\",\"url\":\"/api/uploads/pdf/managed.pdf\",\"description\":\"Verified description\"}]",
 "partnerMediaJson":"[{\"name\":\"Verified partner name\",\"url\":\"/api/uploads/images/managed.png\",\"alt\":\"Logo description\"}]"}
```

Each array allows at most 50 entries. URLs must be managed project media paths.
The editor exposes upload + URL and validated JSON fields, not a separate CMS.
Uploads are public project media and may be orphaned if an editor uploads then
cancels; no automatic file deletion risks existing content. Review retention separately.

### Opportunities / Training

GET `/opportunities/public` and `/training/sessions`: published arrays, deadline
ascending with ID descending tie-break; optional `status` and `category` filters.
GET `/{module}/slug/{slug}`: published details or 404. Expired published records may
be listed as CLOSED, never active. GET `/{module}/admin`: ADMIN list including drafts.
POST `/{module}/admin`, PUT `/{module}/admin/{id}` accept JSON full replacements;
DELETE the same ID path returns 204. No request can supply database ID or audit times.

Shared write fields: `slug`, `title`, `description`, `category`, `location`,
`startDate`, `endDate` (ISO dates), `opensAt` (optional UTC/offset instant),
`published:boolean`, `availability:OPEN|CLOSED|UPCOMING`. Title, valid slug and availability
are required; optional fields may be null. String limits: 255 generally, title 255,
slug 160, description/objectives/methods 10,000, URLs 2,000.

Opportunity adds country, minimumAge/maximumAge (0–150, ordered), applicationDeadline
(instant), applicationUrl (HTTP(S)), relatedProjectUuid (optional existing UUID FK).
Training adds audience, format, language, cost, learningObjectives, trainingMethods,
registrationDeadline (instant), registrationUrl (HTTP(S)). Responses add numeric
`id`, `createdAt`, `updatedAt`, and derived `lifecycle`.

Lifecycle priority: unpublished → UNPUBLISHED; explicit CLOSED, passed deadline,
or endDate before today in Europe/Skopje → CLOSED; explicit UPCOMING or future opensAt
→ UPCOMING; otherwise OPEN. Expiry is inclusive at the exact deadline instant.
Countdown uses real instants, never stored strings. Public action links require OPEN
and a supplied safe URL. End must not precede start; opening must precede deadline.

## Known operational constraints

- No hosted integration is claimed. Staging activation is blocked pending the exact
  evidence and approvals in the deployment checklist. Production was not touched.
- New detail URLs require explicit manifest refresh/rebuild, including newly eligible
  schedules. Existing exported shells refresh content from the API on navigation.
  An already-open page does not receive push notifications of unpublication.
- Editorial JSON textareas are validated structured editors, not a visual rich-text
  composer. Unknown real-world content remains empty. No demo data is seeded on staging.
- Public slug metadata is loaded client-side; no content-specific build-time SEO.
  Deleted/unpublished content at an existing shell shows an unavailable state; arbitrary
  ungenerated URLs return the static server's 404.
- Contact/email remain deferred. Existing public message POST was not expanded;
  only private read/delete authorization was corrected.
- Seven moderate dev-only lint-chain npm findings remain outside the minimal runtime patch.
- Live backup verification, real staging-schema rehearsal, trusted admin review,
  signing-key provisioning and approved admin routing are operator prerequisites.
